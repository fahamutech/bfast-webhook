How it works

From your laptop to a live URL in five moves.

  1. 01

    Scaffold a workspace

    The bfast CLI creates a functions workspace with a functions/ folder and a bfast.json. Run it locally with file-watch reloads.

  2. 02

    Export functions

    Every exported descriptor becomes an endpoint: onRequest for HTTP, onEvent for Socket.IO, onJob for cron, onGuard for middleware.

  3. 03

    Push to GitHub

    A signed webhook reaches BFast Cloud. The HMAC signature is checked with your service's own secret, and only pushes to the default branch of the matching repository deploy.

  4. 04

    Swarm rolls it out

    Docker Swarm replaces tasks one at a time. Each new task clones your default branch, installs dependencies and loads your functions.

  5. 05

    Live over HTTPS

    Traefik routes your hostnames and issues Let's Encrypt certificates automatically. Health and function listings are built in.

bfast-functions

Four descriptors. Everything a backend needs.

Plain JavaScript objects. No framework lock-in, no build step: Express under the hood for HTTP, Socket.IO for realtime, node-schedule for jobs.

HTTP routes

Express request and response objects, any method, any path. Omit path and the route becomes /functions/<name>. Add a description and it appears on the built-in /functions-all page.

export const hello = {
  method: 'get',
  path: '/hello',
  description: 'Greets the caller',
  onRequest: (req, res) =>
    res.json({message: `Hello ${req.query.name}`})
};

Socket.IO events

Each descriptor is a namespace. Reply to the sender, broadcast, announce to everyone, or join topics for rooms.

export const chat = {
  name: '/chat',
  onEvent: ({auth, body}, res) => {
    res.topic(body.room).join();
    res.topic(body.room).announce(body.message);
  }
};

Scheduled jobs

Cron-style rules powered by node-schedule. Reports, clean-ups and reminders live next to the code they belong to.

export const nightlyReport = {
  rule: '0 2 * * *',
  onJob: async () => {
    await sendDailySummary();
  }
};

Guards

Middleware for authentication, rate limits or logging, mounted globally or on a path prefix.

export const apiKey = {
  path: '/orders',
  onGuard: (req, res, next) =>
    req.get('x-api-key') === process.env.API_KEY
      ? next()
      : res.status(401).end()
};

Security

Secure defaults, not optional extras.

Everything that changes your services is authenticated, signed and scoped.

  • Signed deploysGitHub HMAC-SHA256 signatures, with a separate rotatable secret for every service.
  • Google identityFirebase-verified Google accounts with verified email only.
  • Hardened sessionsHttpOnly, Secure, SameSite=Strict cookies with CSRF tokens and exact-origin checks.
  • Secrets stay secretSwarm secrets are write-only and never returned by the API or written to logs.
  • Least privilegeUsers only reach their assigned services. Infrastructure services are read-only.
  • No surprise deletesServices are archived, not deleted, from the console.

FAQ

Questions developers ask.

How do I get access?

BFast Cloud is in early access. Click Request early access or email {{CONTACT_EMAIL}} with your Google account and GitHub repository. We create your service and give your Google account access to the console.

What do I need to deploy?

A GitHub repository containing a bfast-functions workspace. Your package.json dependencies install when the service starts, and the default branch is what runs.

Can I use private repositories?

Yes. Set GIT_USERNAME and a GIT_TOKEN on the service, ideally through a Swarm secret.

How do I store API keys?

Create a Swarm secret in the console, attach it to your service, then set an environment variable to its /run/secrets/… path. The runtime loads the value at start-up.

What happens to a service I'm not using?

Archive it. It scales to zero replicas and keeps its configuration, secrets and hostnames. Unarchive starts one replica again.

Is it open source?

The runtime (bfast-functions), the CLI (bfast-tools) and the deploy webhook are on GitHub. You can run the stack on your own Swarm with the self-hosted plan's help.
